# APOSD Design Critique: `src/`

Sampled 11/30 files in `src/` systematically across file ordering. Two independent assessments via sub-agents, synthesized below.

---

## Tactical Tornado Verdict

**MEDIUM risk (3/12 red flag categories hit).** The codebase shows a dramatic improvement following recent refactoring efforts: global state is now encapsulated via IIFEs across all modules, and nested HTML structures and getters have been simplified. However, a major temporal resource leak and minor information leaks persist. 

The most critical issue found:
- **Event Listener Leak in Video Player** (`src/video-player.js:54-68`): Every time a video modal is opened, new click listeners are attached to the persistent `resumeBtn` and `startBtn` buttons. When a user exits the modal without clicking them, the listeners remain active. Over time, multiple click handlers pile up, resulting in concurrent plays, conflicting time offsets, and duplicate play triggers.

The scan also flagged a naming mismatch: the codebase retains dead `'horizon'` statuses and variables (e.g. `horizonCardsContainer`) that render `'draft'` meetings in the "Coming Up" UI section, creating a disconnect between model structures and visual containers.

## Overall Impression

The codebase represents a solid, strategic piece of engineering. The recent structural changes (specifically, global IIFE encapsulation, template simplification, and module aggregation in `reader-loader.js`) have greatly hardened module boundaries and significantly reduced the codebase's Tactical Tornado risk. 

The primary remaining opportunities reside in fixing the video player's listener accumulation, cleaning up dead files, and completing the IIFE window-binding pattern in `manifest.js` to ensure 100% namespace consistency.

## What's Working

1. **IIFE Encapsulation**: Except for `manifest.js` and `_manifest.js`, all JS modules are 100% self-contained inside IIFE closures. Global state pollution is successfully avoided.
2. **Deep Caching Abstraction**: `fetchMarkdown` in `utils.js` caches promises rather than raw string values, which prevents simultaneous redundant network fetches for identical files.
3. **Rigid Security Barriers**: The path validator (`path.js`) strictly separates repository paths from media assets via domain enums, preventing directory traversal and protocol injection early in the lifecycle.

## Priority Issues

### [P1 Major] Event Listener Leak in Video Player
- **Principle**: Modifying Existing Code (Principle 14) / Obviousness (Principle 13)
- **Complexity Symptom**: Unknown unknowns and runtime side effects.
- **Why it matters**: Attaching click listeners to static DOM buttons (`resumeBtn`, `startBtn`) inside `_setupResumeBar` without freeing them when the player is closed or cancelled leads to handler accumulation. When subsequent videos are opened, clicks on these buttons execute all accumulated click handlers in parallel, setting conflicting times and firing multiple overlapping play commands.
- **Fix**: Remove the inline anonymous handlers in `_videoPlayerCleanup` by saving function references, or bind the handlers only once during application initialization and resolve the target video context dynamically.

### [P2 Minor] Global Namespace Pollution in Manifests
- **Principle**: Information Hiding (Principle 3) & Consistency (Principle 15)
- **Complexity Symptom**: Cognitive load and naming collision risk.
- **Why it matters**: `MANIFEST_DATA` and helper variables (`_processManifestData`) are declared globally outside of IIFEs in `manifest.js` and `_manifest.js`. This breaks structural consistency with the rest of the codebase (where all globals bind explicitly to `window`).
- **Fix**: Define `_processManifestData` inside the `manifest.js` IIFE, export `loadManifest` and `getMeetingRepository` via `window`, and update the build script `inline-manifest.cjs` to output the array inside an IIFE closure binding `MANIFEST_DATA` directly to `window.MANIFEST_DATA`.

### [P2 Minor] Information Leakage of Storage Keys & Prefix
- **Principle**: Information Hiding (Principle 3)
- **Complexity Symptom**: Change amplification.
- **Why it matters**: Namespace prefixes (`'apbc:'`) and storage keys (`'theme'`, `'onboarding_dismissed'`) are hardcoded across multiple files (`theme.js`, `theme-init.js`, `onboarding.js`), coupling these modules directly to browser storage interfaces.
- **Fix**: Move storage-backed operations to high-level getters/setters inside `storage.js` (e.g., `isOnboardingDismissed()`, `dismissOnboarding()`, `getTheme()`, `setTheme(theme)`) so other modules don't touch localStorage directly.

### [P2 Minor] Horizon/Drafts Conceptual & Naming Inconsistency
- **Principle**: Choosing Names (Principle 12)
- **Complexity Symptom**: Cognitive load.
- **Why it matters**: The user interface has transitioned away from the "Horizon" metaphor to plain terms like "Coming Up" and "Drafts." Yet, the code retains a dead `'horizon'` status in `data-meeting.js` and variable/DOM selectors with the "horizon" suffix (e.g., `horizonCardsContainer`, `#horizon-cards-container`), causing a mismatch with the actual draft-rendering pipeline.
- **Fix**: Remove `'horizon'` status from `data-meeting.js`, refactor `renderHorizonCards` to `renderDraftCards`, and rename the DOM ID to `#draft-cards-container`.

## Persona Walkthrough

### Tactical Tornado walkthrough
If the Tactical Tornado wrote this code, they would leave the video player listener leak as is because "it works on first click" and doesn't crash immediately. They would ignore the accumulated handlers and eventually allow the dialog overlay to have 10+ duplicate click listeners firing on every play event, brushing it off as a browser detail.

### Strategic Thinker walkthrough
If the Strategic Thinker were to redesign this, they would modify `_setupResumeBar` to check if listeners are already bound (using a flag or referencing static functions), or they would register the handlers once on boot. During `_videoPlayerCleanup`, they would explicitly clean up any temporary bindings, ensuring zero memory leak or duplicate event firing.
