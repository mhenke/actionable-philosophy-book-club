# Meeting 07: Essential questions

## The Samurai Debate — Matt, John, and Bob in the Cherry Blossom Garden

1. **Deep modules vs short methods (Matt + John/Bob).** Matt Pocock says software fundamentals matter more as AI speeds up generation, and the GitHub debate between John Ousterhout and Uncle Bob treats deep modules as places where complexity gets absorbed so the rest stays simple. Clean Code's short-method advice can push the other way. When does splitting code into many small pieces move complexity to the interfaces instead of removing it, and how do you spot that in our codebase — entanglement, shaky abstractions, the PrimeGenerator classitis?

2. **Strategic vs tactical in the age of agents (Bob + John).** Uncle Bob argues fundamentals carry more weight now, not less, and in his LIVE session treats deterministic scaffolding (compilers, type systems, CRAP, mutation testing in the Hardener) as the check that keeps scaffolding over steering. John pushes strategic design and bundling over tactical TDD myopia. Agents make tactical edits cheap and tempting. Where does quick generation pay off and where does it decay the design a little on every change, and what scaffolding check would have caught it?

3. **Comments, names, and what must be obvious (John vs Bob).** John treats comments as part of abstraction and his side of the GitHub debate rejects megasyllabic names, designing for the reader vs the author. Bob in Clean Code leans on expressive code and smaller steps and says comments are failures. After watching the two YouTubes and reading the GitHub thread, when is a comment a design failure and when is it the missing fact — intent, side effect, invariant — the reader needs where they stand?

4. **Testing that earns its keep (Bob + John).** Common ground in the GitHub exchange is that good tests and coverage make larger, cleaner changes possible, and both sides of the debate plus Bob's LIVE agree on that guardrail. The disagreement is how you get there — Three Laws vs bundling, Hardener vs writer-first tests that still pass the scaffold. What does coverage that actually affords a refactor look like compared to coverage that just counts lines, and what kind do we have today?

5. **Managing the AI complexity frontier (all three).** All three sources agree fundamentals are the ultimate defense against AI-driven degradation into garbage and agent thrashing, and the disagreement shifts to workflow. What must we fix first: a shared ubiquitous language/terminology file so AI and humans share the same design concept, a rigid deterministic scaffolding (mutation, complexity checks, Hardener) to catch the tactical tornado, or deeper interfaces so we can safely delegate implementation to the machine? Which one should we carry into the next series?
