# Choose Your Next Direction

The Empirical Reality Check tested Ousterhout's theories against data. Now the group votes on what comes next.

---

## Path 1: Complete the Textbook

Return to A Philosophy of Software Design. Chapters 9-19 cover error handling strategies (define errors out of existence), design for change, layered design, gracefully pulling complexity downward, and tactical vs. strategic programming. The empirical lens from Meeting 03 calibrates every concept against real data.

**Roughly 30-40 pp per meeting. Textbook-first, code-discussion-second.**

---

## Path 2: Architecture Design Studio

Practice over theory. Each meeting tackles a design problem: extract a deep module boundary, refactor a shallow module, design an API using the Friction Checklist, or run a Vocabulary Audit on a real codebase. Readings are short case studies and code excerpts rather than full chapters.

**Roughly 10-15 pp per meeting. Code-first, reading-discussion-second.**

---

## Path 3: Systems Under Load

Follow the runtime tax thread. Deep-dive into hardware constraints, profiling methodology, JVM internals, and abstraction collapse at scale. Readings from Doug Lea, Java concurrency, mechanical sympathy literature, and production postmortems. For the performance-minded engineer.

**Roughly 20-25 pp per meeting. Benchmark-first, theory-discussion-second.**
